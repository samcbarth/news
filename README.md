# The Quillmark (news.samcbarth.com)

News hub for the samcbarth.com network. It pulls headlines from the six network sites' news feeds and links each one back to the site that published it, plus a small set of hub-only stories under `/story/`. Shared network rules: `C:\SamSites\NETWORK.md`.

Plain static HTML/CSS/JS generated by `build.py` (Python 3, standard library only). Pillow is only needed for `make_images.py`.

## Build and preview

```bash
python build.py            # production build into the repo root (pulls live feeds)
python build.py --test     # test build into _preview/ (local sibling feeds or sample data)
python check_links.py      # internal link check of the production build (add --preview, --external)
python -m http.server 8827 # then open http://localhost:8827/ (test build at /_preview/)
```

The `.claude/launch.json` entry `news` serves the repo on port 8827.

## How the feed pull works

- `site.json` lists the six sections and their feed URLs: `https://<sub>.samcbarth.com/news/feed.json` (JSON Feed 1.1).
- **Production build** fetches each feed live. A good copy is saved to `data/feed-cache.json`; if a fetch fails later, the cached copy is used. A site whose feed has never loaded shows a short "has not published yet" note in its rail.
- **Browser refresh**: pages re-fetch the feeds that answered at build time and add any newer headlines to the Latest list and rails. Feeds that were unreachable at build time are not fetched in the browser, so pages do not log network errors before a site's DNS is live. Rebuild after each sibling site goes live.
- **Test build** (`--test`) reads `C:\SamSites\<sub>\news\feed.json` when it exists (override the parent folder with `SAMSITES_DIR`), otherwise the sample feeds in `_testdata/`, and writes to `_preview/` with a red TEST banner and `noindex`.

Items need `url` (absolute https, or a root-relative path that gets the site's domain), `title` and `date_published`. `summary`, `image` and `tags` are optional. Items without a URL, title or date, or with a non-https URL, are skipped. A local feed that is not valid JSON falls back to the sample.

### Test data never ships

`_testdata/` sample feeds set `"_test": true` and every title starts with `[TEST]`. Production builds drop those items, and `build.py` aborts if any test marker reaches the published pages. `_testdata/` and `_preview/` start with `_`, so GitHub Pages (Jekyll) does not serve them; `_preview/` is also gitignored. Regenerate samples with `python _testdata/make_samples.py`.

## How to add a hub story

Add one file to `stories/`, named `<slug>.json`:

```json
{
  "slug": "same-as-the-filename",
  "section": "realestate | tools | games | streaming | homerepair | deals",
  "title": "Headline",
  "dek": "One-sentence summary (also the meta description).",
  "date_published": "2026-11-09T09:00:00-06:00",
  "date_modified": "optional, same format",
  "tags": ["optional"],
  "body": [ {"h": "Question heading?"}, {"p": "Direct 1 to 2 sentence answer, then detail."} ],
  "sources": [ {"label": "Publisher, title (date)", "url": "https://primary-source"} ]
}
```

Then run `python build.py`. Rules (NETWORK.md): real, verifiable facts only, every story links its primary source, original wording, at most one short attributed quote, no em dashes, no emojis, no hype verbs. The in-article ad slot goes after the third paragraph automatically.

## Where config ids go

`assets/config.js` (no rebuild needed):

| Key | What | Status |
|---|---|---|
| `ADSENSE_CLIENT` | `ca-pub-...` | Waiting on AdSense approval. Empty = no ad slots render. |
| `ADSENSE_SLOTS` | Optional ad-unit id per slot | Optional |
| `HUBSPOT_FORM_ID` | Contact form on portal 20693956 | **Needed**: the contact page says "being set up" until this or `CONTACT_EMAIL` is filled |
| `CONTACT_EMAIL` | Fallback mailto on the contact page | Optional if the form id is set |
| `AMAZON_TAG` | Not used on the hub | n/a |

Ad slot positions: after the lead block, between rails 2/3 and 4/5, sidebar (desktop), in-article after paragraph 3, end of article, section page middle and end.

`ads.txt` lives at the root domain samcbarth.com (HubSpot), not here.

## DNS record Sam needs (Squarespace)

| Type | Host | Value |
|---|---|---|
| CNAME | `news` | `samcbarth.github.io` |

Then in the GitHub repo: Settings > Pages > deploy from `main` / root, custom domain `news.samcbarth.com` (the `CNAME` file is already here), and turn on Enforce HTTPS.

## Files

- `build.py`: generates every page, `feed.xml` (RSS), `feed.json` (hub stories, JSON Feed 1.1), `sitemap.xml`, `robots.txt`, `llms.txt`.
- `site.json`: masthead, sections, feed URLs, network bar.
- `stories/`: hub-only stories, one JSON file each.
- `assets/`: `style.css` (samcbarth.com brand tokens from NETWORK.md "Brand", dark only), `app.js` (sticky nav, ads, contact form with brand styles injected into HubSpot's form iframe, feed refresh), `config.js`, `favicon.svg`, `og.png`, `logo.png` (from `make_images.py`).
- `data/feed-cache.json`: last good copy of each live feed.
- `check_links.py`: link checker.
